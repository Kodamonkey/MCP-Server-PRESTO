# report.html Template

`report.html` is a modern, **offline** scientific dashboard generated by
`html_report_builder.build_html()`. It is plain HTML + embedded CSS + minimal
vanilla JavaScript — no React/Vue, no build step, no external CDNs.

## Design constraints

- Works fully offline; open the file directly in a browser.
- CSS embedded in a `<style>` block (no network fetch).
- One small vanilla-JS function for a sortable candidate table.
- All asset links are **relative** to `outputs/<run_id>/`
  (`visuals/…`, `thumbnails/…`, `waterfalls/…`, `candidates/…`).
- Optional self-contained mode (`ReportOptions.self_contained_html=true`)
  base64-embeds images into the HTML. Off by default — it bloats the file.

## Sections

| # | Section | Content |
|---|---------|---------|
| A | Header | run name, run_id, input file, generation date, status, badges (candidates / RFI / visuals / waterfalls) |
| B | Observation Summary | file type, telescope/instrument, duration, frequency, bandwidth, channels, sampling time, start MJD, source name (only if present) |
| C | PRESTO Workflow Summary | tools executed, failed tools, total runtime, DM trials, warnings |
| D | Candidate Overview | totals by type, link to `candidates.csv` |
| E | Candidate Table | sortable/filterable table — id, type, DM, SNR/σ, time, period, accel/z, rank, RFI hint, links |
| F | Visual Diagnostics Gallery | thumbnail grid linking to full visuals + waterfalls |
| G | Candidate Detail Cards | per-candidate card — metadata, waterfall image, collapsible raw JSON |
| H | RFI and Data Quality | mask files, bad channels/intervals, masked fraction, notes |
| I | Interpretation Notes | conservative language — plausible candidates vs likely RFI/noise vs insufficient evidence; **never** claims a discovery |
| J | Reproducibility | tools executed, artifact links, links to `manifest.json` / `summary.json` / `status.md` / `timeline.json` |

## Scientific language

Section I is deliberately cautious. It uses labels like *plausible candidate*,
*FRB-like candidate*, *pulsar-like periodic candidate*, *requires human
inspection*, *likely RFI/noise*. It never prints "confirmed FRB", "confirmed
pulsar" or "confirmed transient".

## Styling

A light scientific-dashboard theme: card sections, an accent-coloured heading
rule, a sticky sortable table header, a responsive thumbnail grid, dark code
blocks for raw JSON. CSS variables (`--bg`, `--fg`, `--acc`, …) keep it easy to
retheme. CSS may instead be served from `outputs/<run_id>/assets/style.css` —
the default embeds it for single-file portability.

## Customizing

Edit `src/presto_mcp/reporting/html_report_builder.py`:

- `_CSS` — the embedded stylesheet.
- `_JS` — the `sortTable` function.
- `build_html()` / the `_section_*` helpers — section content and order.

Keep it dependency-free and offline. Escape all dynamic text with
`html.escape()`.
